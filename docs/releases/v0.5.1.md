# Weblab v0.5.1

This patch release improves Agent console interaction and response formatting,
with particular attention to smaller self-hosted models. It includes fixes for
both Ollama and OpenAI while preserving existing approvals and console locks.

## Console reliability

- Initial console reads return recent output instead of starting at old boot
  logs. Omitted history is identified explicitly; cursor-based continuation
  preserves subsequent output without skipping bytes.
- Incomplete captures cannot be used to request console input through the Agent.
  The model must continue reading and inspect the current prompt first.
- `send_console_command` accepts one ordinary command and appends Enter. This
  avoids models typing literal `\r` or leaving a command unsubmitted. Raw
  `send_console_input` remains available for Enter, control keys and pager input.
- Missing reads, mismatched cursors and mismatched observation revisions have
  distinct recovery messages. A CLI prompt such as `SW4#` is not a console cursor;
  these errors are explicitly distinguished from missing approval.
- Ollama uses compact discovery pages and console chunks to reduce downstream
  tool-output truncation. Returned offsets/cursors allow the model to continue.
  OpenAI keeps its ordinary response budgets.

These tools keep the same console-input permission, exact-action approval or
session YOLO, revision/cursor validation and human input locks. No command is
silently repaired, retried or replayed after a rejected request.

## Agent presentation and guidance

Agent replies now render Markdown headings, emphasis, lists, tables and code
blocks. Wide tables and code blocks scroll; model-provided HTML, images and links
remain inactive. User messages and exported transcripts retain their text.

The OpenAI model field recommends `gpt-6.1-sol` based on the maintainer's reported
lab experience; availability depends on the account. A new
[console guide](../agent-console-guide.md) explains privilege levels, pagination,
command submission and complete-output checks for agents and operators.

## Remaining limitations

Smaller local models can still omit tools, misread CLI context, use old output,
choose the wrong interfaces or misinterpret a tool error. Successful individual
inspection and configuration tasks do not establish reliability across all labs.
See [known model and console issues](../agent.md#known-model-and-console-issues).
Verify device output rather than treating an accepted input or completed model
turn as proof of success.

Authentication/roles and remote-test features are not included in this patch.
There are no changes to the hosted demo deployment.

## Upgrade

Use matching Linux amd64 core and optional companion images:

- `ghcr.io/weblab-network/weblab:0.5.1`
- `ghcr.io/weblab-network/weblab-exos:0.5.1`
- `ghcr.io/weblab-network/weblab-agent:0.5.1`

The release also updates `latest`. Follow [Agent setup](../agent.md) or the
[installation guide](../installation.md), keeping your existing mounts, Compose
project name and Agent volumes. Update both core and companion; update the
optional external MCP adapter as well. Source installations require a rebuild.
Reload browser tabs after upgrading. Start a new conversation if an older thread
keeps repeating obsolete tool assumptions; existing history remains available.

Save configurations and export a stopped-lab ZIP before upgrading. Shut down
Junos gracefully from its console before stopping its process. Do not use
`down -v`, which removes named Agent state volumes.

## Validation scope

Release checks cover disposable backend/console tests, MCP adapter integration,
Agent and workspace browser regressions, and container/tool-transport checks.
Live maintainer feedback includes successful local-model task verification and
configuration after the console fixes. This is not comprehensive vendor/protocol
validation or a guarantee of model behavior; no paid model account is required
for the automated regression checks.
