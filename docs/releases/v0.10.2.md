# Weblab v0.10.2

New LL2S switches and the fresh-install preload use
`ghcr.io/weblab-network/ll2s:0.2.0-ovs-rstp1`. This image includes the OVS 3.7.1
RSTP root-selection patch. We retested the original Cisco MST / LL2S RSTP topology
and confirmed that the lower-cost uplink is selected correctly. LL2S still uses
one STP/RSTP tree; this does not add MSTP or PVST+ support.

Existing `ghcr.io/weblab-network/ll2s:0.2.0` and `ll2s:dev` nodes retain their
selectors, configuration storage and exact saved-ZIP image checks. The old
selector appears in the catalog when used by a lab. An upgrade does not retag
images or change running switches.

To compare an existing topology with the patched image, save inside each switch,
stop it and export **JSON + saved configs**. Keep the original, then change the
LL2S image selectors in a copy and import into a separate workspace or with fresh
node IDs. Saved storage is separate for each node/image selector. Do not rename
images inside a saved-state ZIP or retag the original release to bypass identity
checks. See [saving and restoring](../backups.md).

Use matching **0.10.2** core, Agent and EXOS images. The installer and examples
select the patched LL2S release. Weblab FRR remains **10.7.1-wl1**.
Pull the new LL2S image on Weblab's Docker host; Weblab does not pull on Start.
Existing installations should back up and stop their lab before recreating the
Weblab service, retaining their volumes.

See the [LL2S release and corresponding sources](https://github.com/weblab-network/ll2s/releases/tag/v0.2.0-ovs-rstp1)
and [device guide](../devices.md#ll2s-linux-layer-2-switch).
