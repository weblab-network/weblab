# Weblab v0.3.0

This release adds optional IOL cable unplug control, FRR VRRP and Linux shell
access, support for explicitly allowed custom FRR images, and console reliability
fixes.

A shared **[live demo preview](https://demo.weblab.network/)** is available to
explore the workspace and device consoles with restricted controls.

## New functionality

- **Optional IOL cable unplug control:** a saved per-node checkbox enables L1
  control on the tested IOL 17.18.02 profiles. It is off by default because IOL's
  `-l` mode can consume a full CPU core. Stop all nodes before changing the
  setting. Directional traffic blocking remains available without L1 control.
- **FRR VRRP:** `vrrpd` is enabled in the standard FRR profile. Configure the
  required Linux VLAN/macvlan interfaces through the console shell; see the
  device guide for an example.
- **FRR Linux shell:** leave the top-level `vtysh` prompt with `exit` to open
  Bash, and run `vtysh` to return. Exiting Bash reopens the CLI in the same
  container. Shared-console input locks still apply.
- **Custom FRR images:** opt in with `WL_ALLOW_UNTESTED_FRR=1` or
  `--allow-untested-frr` to use a modified image under the existing FRR profile
  tag. The UI and launcher warn when the image is untested. Startup uses its
  immutable image ID; ZIP restore still requires the exact saved image.

## Console fixes

- EXOS, IOSv and vEOS no longer terminate QEMU when Ctrl+C is typed in their
  serial consoles. All QEMU profiles now send terminal control bytes to the
  guest instead of interpreting them as host signals. Junos already used this
  console setting.
- Native IOL Ctrl+C is translated to the IOS interrupt sequence after input-lock
  checks, avoiding the emulator termination observed with literal Ctrl+C.
- Logging out of an Alpine shell reopens the console without stopping or
  recreating the PC container. Repeated rapid failures have bounded recovery.

## Upgrade and compatibility

Standard image: `ghcr.io/weblab-network/weblab:0.3.0`.
Bundled EXOS edition: `ghcr.io/weblab-network/weblab-exos:0.3.0`.
Both editions also publish `latest`; images target Linux amd64.

Save device configurations and export a stopped lab ZIP before upgrading.
For Junos, use `commit`, then `request system power-off` from operational mode
and wait for completed guest shutdown before stopping Weblab. Pull/recreate the
Weblab container while retaining image/data volumes. A browser refresh cannot
apply the console launcher changes to existing device processes.

Existing topologies/archives without `iol_l1` default to L1 control **off** on
next launch. To use cable unplug actions, select **Enable cable unplug control**
on the relevant stopped IOL nodes and apply their settings. Traffic-loss actions
remain independent of this preference.

FRR's tested image remains `quay.io/frrouting/frr:10.7.1`, pulled separately on
the Docker host, as is `alpine:latest` for PCs. Untested-image permission is a
server option, not a topology setting. It does not disable archive integrity or
image matching and does not add arbitrary FRR tags. Distribute custom images
separately with Docker save/load; lab ZIPs do not contain them. Custom-image ZIPs
need this release or a compatible importer.

Linux-created VLAN/macvlan interfaces and shell changes are not persisted by
FRR `write memory` or lab ZIP export. Recreate them after container recreation;
the saved `frr.conf` continues to be restored separately. Junos real-guest ZIP
restore coverage and automatic graceful shutdown remain outstanding.

See the [device guide](https://github.com/weblab-network/weblab/wiki/Device-profiles),
[console guide](https://github.com/weblab-network/weblab/wiki/Consoles), and
[link actions](https://github.com/weblab-network/weblab/wiki/Link-failures).
