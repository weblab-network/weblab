# Weblab v0.2.0

This release adds FRRouting container routers, Juniper vJunos profiles,
topology group movement, and smaller lossless vEOS backups.

## New functionality

- FRR 10.7.1: up to eight interfaces, shared vtysh consoles, initial and saved
  configuration, ZIP backups, directional traffic loss and carrier controls.
  Includes an original FRR/Alpine OSPF exercise; no KVM or vendor image needed.
- vJunos-switch and vJunosEvolved 26.2R1.7: device selection, console access,
  topology links and persistent disk overlays. Evolved has a stable VM UUID.
  vJunos-switch requires a bare-metal Intel host; see the device guide.
- Multi-select: use Shift/Ctrl/Meta-click or the touch-friendly Multi-select
  button, then drag a selected node to move the group while preserving spacing.
- Compact vEOS ZIPs: lossless references to the matching base image reduce
  repeated data without changing the saved disk. Restore verifies checksums.
- Junos Stop confirmation: individual and whole-lab Stop actions remind users
  to shut down Junos through its console first.

## Upgrade and compatibility

Standard image: `ghcr.io/weblab-network/weblab:0.2.0`.
Bundled EXOS edition: `ghcr.io/weblab-network/weblab-exos:0.2.0`.
Both editions also publish `latest`. Images target Linux amd64.

Save device configurations, shut down guests as required, and export a stopped
lab ZIP before upgrading. Retain the existing image and data volumes when
recreating Weblab. Pull `quay.io/frrouting/frr:10.7.1` separately on the Docker
host for FRR, and `alpine:latest` for PCs. Juniper images remain user-supplied.

Existing version-1 ZIPs remain importable. Compact vEOS and FRR archives use
version 2 and need a compatible importer; disable vEOS compaction for an older
importer when the lab has no FRR nodes. Junos ZIP coverage currently includes
synthetic-disk round trips; full real-guest restore verification remains pending.

## Junos shutdown and validation

**Save with `commit`, return to operational mode, run
`request system power-off`, and wait for guest shutdown before Stop node,
Stop lab, or stopping the Weblab container.** Abrupt termination has caused
vJunos-switch filesystem damage and subsequent boot failure. The confirmation
is a reminder; Weblab does not automatically run or verify guest shutdown.

Both profiles have been repeatedly boot-tested by a user. Bare-metal switch
VLAN/trunk forwarding and inter-VLAN traffic through FRR were verified in a
user-run lab. Evolved forwarding coverage remains incomplete. Initial snippets,
configuration-text exports and Junos carrier control are not implemented.
