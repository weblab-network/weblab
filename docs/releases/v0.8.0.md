# Weblab v0.8.0

For the core, optional Agent and EXOS edition, use [v0.8.1](v0.8.1.md).
An offline image-validation error blocked the v0.8.0 EXOS/release workflow.
This release remains the source and binary distribution reference for the
unchanged Weblab FRR `10.7.1-wl1` package.

This release adds **Weblab FRR**, an optional FRRouting 10.7.1 container with
native CLI integration for LLDP, read-only SNMPv2c, routed VLAN interfaces and
IPv4 VRRP provisioning. It works with LL2S switches for VLAN trunks,
router-on-a-stick and redundant virtual gateways without vendor images or KVM.

## Install the FRR package

The Linux amd64 image selector is
`ghcr.io/weblab-network/weblab-frr:10.7.1-wl1`. Install the image on the same
Docker host as Weblab. The release provides:

- `weblab-frr-linux-amd64.tar.gz`: load with `docker load -i`;
- `weblab-frr-sources.tar.gz`: exact FRR source, patch, helpers, build recipe and
  dependency sources/recipes;
- `image.json` and `SHA256SUMS`: identity and artifact checksums.

Verify the downloaded files with `sha256sum -c SHA256SUMS`. After registry
publication, `docker pull ghcr.io/weblab-network/weblab-frr:10.7.1-wl1` installs
the same image. Add a Router and select this image. Weblab verifies the immutable
image/config ID; no experimental opt-in is needed for this release artifact.
Source builds remain available and require `WL_ALLOW_UNTESTED_FRR=1`.

See the [setup and CLI guide](../../packaging/frr/README.md) and
[source distribution notes](../../packaging/frr/SOURCES.md).

## What the CLI adds

| Feature | Commands and behavior |
| --- | --- |
| LLDP | `lldp run`, per-port transmit/receive, `show lldp neighbors detail`; meaningful Weblab FRR system description |
| SNMPv2c | Opt-in read-only system, IF-MIB/ifX and LLDP-MIB; explicit listener address, source CIDR and community |
| VLAN routing | `vlan interface eth0.10` creates a routed 802.1Q interface; ordinary FRR commands configure addressing and routing |
| IPv4 VRRP | Native `vrrp` commands provision required virtual interfaces; `show vrrp platform` reports provisioning while `show vrrp` reports protocol state |

LLDP and SNMP default off. SNMPv1/v3, writes, traps and routing-protocol MIBs
are not included. VLAN support is routed subinterfaces, not switch access ports
or bridge VLAN management. VRRP provisioning supports IPv4 on physical/VLAN
interfaces in the default VRF; IPv6, VRFs, autoconfigure and address-owner mode
are outside this integration. FRR itself retains control of VRRP elections,
advertisements, priority and preemption.

Use `write memory` before Stop. Saved configuration reconstructs the extension
settings and VLAN/VRRP interfaces on Start. Lab ZIPs retain configuration and
exact per-image identity; they do not contain Docker images or unsaved edits.

## Upgrade and compatibility

Save configurations and export backups before upgrading Weblab. Update the core
and, if used, the matching optional Agent through the existing Compose procedure.
The FRR package is a separate node image, not a service added to the core container.

The stock `quay.io/frrouting/frr:10.7.1` profile remains unchanged. Earlier local
extension tags retain their opt-in and saved storage. Changing a node's image
selector selects different storage; it does not migrate its configuration. Keep
the existing selector for existing labs, or transfer saved configuration text to
a new router and verify it there. ZIP restore requires the original exact image.

LL2S remains at v0.2.0. Optional authentication, roles, shared instructions and
administrator Agent access from v0.7.0 remain available; this release does not
add named users or an administrator control panel. A starter appliance and
Docker-in-Docker distribution remain future work.
