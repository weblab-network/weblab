# Weblab v0.6.0

This release adds workspace layouts and Agent usage visibility. Keep a full-height
topology beside your consoles and Agent, see remaining OpenAI account allowance,
and retain elapsed time after a turn finishes.

## Workspace layouts

Choose **Layout** in the topology toolbar:

- **Build**: library and inspector beside the topology, consoles below.
- **Side by side**: topology beside a full-height Consoles, Agent or Instructions pane.
- **Agent workspace**: topology beside Agent/Instructions above grouped consoles.
- **Free layout**: existing floating windows and tiling controls.

Drag or keyboard-resize the dividers. Devices and Inspector use temporary drawers
in working layouts. The browser remembers the preset, selected tools and splits;
narrow screens use a stacked arrangement. Switching layouts preserves console
connections, scrollback, input locks, Agent conversations and drafts. Instructions
remain available without the optional Agent.

Docked tools share a compact header and no longer retain floating-window borders.
An empty Instructions pane explains how to open a file. The Agent message box
grows as you type and accepts drafts and attachments during generation; Send
waits for the current turn to end and drafts are never automatically submitted.

## Allowance, tokens and elapsed time

The existing activity line shows OpenAI account allowance when available, with a
details popup for reset times, last check and manual refresh. This is account-wide
allowance shared with other Codex sessions, not a per-turn charge. Missing or stale
readings are labelled; Weblab does not assume an allowance has refilled.

Provider-reported token counts cover the current/latest turn and conversation,
with cached-input and reasoning breakdowns. Ollama counts appear when supplied
by the provider. A turn can include many model requests and repeated context;
total tokens are not just generated output. There are no monetary cost estimates.

Completed, interrupted and failed turns retain their elapsed duration beside the
status and in usage details, including tool calls and approval waits. Recorded
duration and token counts survive history reopening and companion restarts. Older
turns without recorded timing do not receive an estimated duration.

See [workspace layouts](../topology.md#workspace-layouts) and
[Agent usage with screenshots](../agent.md#allowance-and-token-usage).

## Scope and upgrade

The v0.5.1 console tools, model instructions, approvals, cursor checks and input
locks are unchanged. Known model/console limitations still apply; this release
does not add automatic login, privileged-mode entry or pager handling.
Authentication and account roles are not included. The hosted demo deployment
is unchanged.

Use matching Linux amd64 core and optional companion images:

- `ghcr.io/weblab-network/weblab:0.6.0`
- `ghcr.io/weblab-network/weblab-exos:0.6.0`
- `ghcr.io/weblab-network/weblab-agent:0.6.0`

Follow [installation](../installation.md) and [Agent setup](../agent.md), preserving
the existing Compose project, mounts and Agent volumes. Update both core and
companion for the new usage display. Source installations need a rebuild; reload
browser tabs afterward. The Agent remains optional: omit its Compose override
for an installation without it.

Save device configurations and export a stopped-lab ZIP before upgrading. Shut
down Junos gracefully from its CLI before stopping its process. Do not use
`down -v`, which removes named Agent state volumes.

## Validation scope

Disposable backend and browser regressions cover usage/history, layout changes,
console connection and lock continuity, instructions, drafts and mobile bounds.
Allowance tests use simulated provider events and do not consume an account's
quota. Website checks cover desktop/phone layouts, expandable media and operation
without JavaScript. No new live-model benchmark or guest protocol test is claimed.
