# Weblab v0.5.0

This release adds an optional Agent window for creating and checking practice
labs through Ollama or OpenAI, alongside the topology and device consoles.
Ordinary Weblab remains usable without an Agent, model server or model account.

## Agent workspace

- Float, resize and arrange the Agent window with the other workspace panels.
  Conversation, Operations, Proposals, History and Settings have separate tabs.
- Connect an operator-selected Ollama endpoint/model, or sign in with your own
  ChatGPT account using a device code. Model availability and usage limits depend
  on the provider/account; Weblab does not include model weights or subscriptions.
- Ask for topology proposals, review them and download topology JSON/exercise
  instructions. Preview guidance flags disconnected switch groups and missing
  redundant switch paths for STP exercises.
- Enable topology changes/node starts and console input separately. Each action
  normally needs browser approval; optional session YOLO preapproves only enabled
  actions. Revision checks, console cursors, human locks and turn limits remain
  enforced. The default is read/preview.
- Approval requests open a modal while Operations retains the record. Choose
  Later to review elsewhere, or enable session YOLO when approving to preapprove
  subsequent actions allowed by the existing permissions.
- Activity status, elapsed time, visible tool errors, Stop and reconnect controls
  help follow a turn. Activity indicators do not display private model reasoning.
- Console tabs support mouse-wheel scrolling when they overflow.
- Starter guidance hides when the conversation begins, and the prompt becomes a
  follow-up message field after the Agent responds. The OpenAI model prefill is
  `gpt-5.6-sol`; choose a model available to your account.

## History and attachments

History supports reopening, renaming, deleting and downloading conversations.
It belongs to the browser's Agent session, with up to 50 conversations and a
24-hour inactivity expiry. Optional remembered browser access is off by default.
Opening history does not replay earlier approvals or operations.

Attach PNG/JPEG/WebP screenshots with an image-capable model, or UTF-8 text and
configuration files. Limits are four files, 2 MiB combined and 64 KiB combined
text per message. `gpt-oss` is text-only; PDF and office files are not supported.
Files are reference material, not automatically executable/imported lab state.

The Export dialog can optionally include the selected Agent conversation in
ZIP or JSON. ZIP contains Markdown/JSON reference transcripts; JSON contains
optional metadata. Text attachments are included, screenshots listed by filename.
Import does not restore an Agent session or replay actions. Login data, session
tokens, approvals and internal tool logs are excluded; message text itself may
contain sensitive information and is not automatically redacted.

## Installation and upgrade

Linux amd64 images:

- `ghcr.io/weblab-network/weblab:0.5.0`
- `ghcr.io/weblab-network/weblab-exos:0.5.0`
- `ghcr.io/weblab-network/weblab-agent:0.5.0` (optional companion)

These also publish `latest`; use matching numbered core/companion versions for
controlled upgrades. Add `compose.agent.prebuilt.yaml` to the normal prebuilt
Compose deployment, or use `compose.agent.yaml` when building from source.
See [Agent setup](../agent.md) for the complete commands and account settings.

Save device configurations, gracefully shut down guests and export a stopped-lab
ZIP before upgrading. Junos needs `request system power-off` before Stop. Keep
existing image/data mounts, Compose project name and Agent named volumes;
`down -v` removes conversation/login state. Reload browser tabs after recreation.
Update the optional external MCP adapter alongside Weblab.

The companion uses dedicated socket/state volumes, no network interface, no
Docker socket and no guest-disk mounts. The gateway limits model destinations and
Weblab operations. The current OpenAI login integration is for owner-operated
self-hosted use; it is not a public hosted login service. The hosted restricted
demo is maintained separately and is not upgraded by this release.

## Scope and validation

Agent output needs verification: a completed turn is not proof of correct device
configuration. Smaller local models may struggle with boot output, topology
design and multi-step tasks. Stop/delete, live link manipulation and image upload
remain manual in the embedded Agent. Provider login does not add Weblab user
accounts or make an Internet-exposed workspace safe.

Release checks use disposable labs and include backend/browser regressions,
packaged core/companion startup, session persistence and pinned Codex/MCP tool and
attachment transport against a simulated model. They do not require a real
OpenAI account or paid inference and do not establish protocol/backup coverage
for every vendor. Real guest Junos ZIP restoration remains a separate test.

The preparation run passed 238 backend tests and 11 browser suites, plus the
external MCP capability tests and isolated container checks. Both core and
companion were built with BuildKit. Hosted CI publication and anonymous registry
pulls are verified separately when the release is published.
