# Weblab v0.8.1

This patch release includes the Weblab FRR features introduced in
[v0.8.0](v0.8.0.md) and fixes offline topology validation with `--image-dir`.

The validator did not initialize the FRR catalog setting, causing an
`AttributeError` when checking installed VM/IOL image filenames. This also
blocked the v0.8.0 EXOS image and release workflow. The running server already
initialized this setting; the fault was in the standalone validation tool.
A regression test now checks the EXOS example with present and missing images.

Use **v0.8.1** for the core, optional Agent and EXOS edition. Save configurations
and export backups before following the usual Compose upgrade procedure.
The existing v0.8.0 Git tag is unchanged.

## Weblab FRR package

The optional node image remains
`ghcr.io/weblab-network/weblab-frr:10.7.1-wl1`, with the same immutable image ID
and the same tested LLDP, read-only SNMPv2c, routed VLAN and IPv4 VRRP support.
It has not been rebuilt for this validator fix.

Its binary archive, corresponding source archive, `image.json` and `SHA256SUMS`
remain attached to the [v0.8.0 source release](https://github.com/weblab-network/weblab/releases/tag/v0.8.0),
matching the image's provenance label and repository checksum lock. Verify with
`sha256sum -c SHA256SUMS`, then use `docker load -i weblab-frr-linux-amd64.tar.gz`
or pull the published image tag.

See the [FRR setup and CLI guide](../../packaging/frr/README.md) for configuration,
persistence and supported scope. Existing FRR and LL2S images and saved lab data
retain their previous behavior.
