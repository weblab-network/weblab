# Weblab v0.4.0

This release adds LL2S container switches, an optional external-agent MCP adapter,
and storage monitoring with capacity checks.

## Switching and routing without vendor images

- Pull `ghcr.io/weblab-network/ll2s:0.2.0` on Weblab's Docker host and load its
  `openvswitch` module. Select that image directly in the switch Inspector.
- LL2S provides access/trunk VLANs, STP/RSTP, LLDP and optional management IPv4
  with read-only SNMPv2c. It needs no KVM. Its source, help and dependency sources
  are published in [weblab-network/ll2s](https://github.com/weblab-network/ll2s).
- Combine it with separately pulled `quay.io/frrouting/frr:10.7.1` and
  `alpine:latest`. Included RSTP/VLAN and LL2S/FRR OSPF exercises provide
  importable topologies and instructions.
- LL2S supports fresh-device snippets and saved configuration export/restore.
  Interactive `end` commits; `write memory` saves. ZIP archives preserve the
  saved configuration and exact launch-image identity, excluding unsaved changes.
- Recovery handles a missing LL2S container after a host restart while retaining
  host-saved state and removing only verified owned, unused network resources.

Existing `ll2s:dev` labs remain supported with their original selector and storage
paths. Keep that selector for a configured lab: changing a node's image selects
separate saved storage. Restore still requires the archive's exact image ID.
LL2S uses one spanning tree across VLANs; MSTP and BPDU guard are not implemented.

## Optional agent integration

Enable `WL_AUTOMATION=1` and install the separate STDIO MCP adapter in your MCP
client environment. The client chooses its model, including compatible local
models; Weblab has no built-in chat panel or model account requirement.

Read-only tools discover profiles, status, storage and console output. Topology
previews accept simple node aliases and generate persistent IDs and link IDs.
Separate adapter opt-ins expose apply/start and console input. Stale topology
revisions and console cursors are rejected, and shared input locks remain in use.
Console capture timeouts do not imply command completion.

Automation is disabled by default. This release does not add authentication or
user isolation: keep the server on loopback/a trusted network or use an SSH tunnel.
Client tool approvals are separate from server access. See the
[MCP guide](https://github.com/weblab-network/weblab/wiki/AI-assistants-and-MCP).

## Storage visibility and checks

The Storage button and API report host filesystem headroom and allocated bytes
for node disks/logs, including retained directories. Measurements use metadata
and do not open active guest disks. The MCP adapter exposes the same report.

Starts, uploads, exports and staged restores check minimum available space.
These checks do not reserve disk space or automatically delete files. Guest
trace cleanup does not necessarily reduce host QCOW2 allocation; automatic Junos
shutdown and offline compaction are not included.

## Upgrade

Standard image: `ghcr.io/weblab-network/weblab:0.4.0`.
Bundled EXOS edition: `ghcr.io/weblab-network/weblab-exos:0.4.0`.
Both publish `latest`, for Linux amd64. LL2S, FRR and Alpine remain separate pulls.

Save configurations and export a stopped lab ZIP before upgrading. For Junos,
commit, run `request system power-off` and wait for shutdown before stopping
Weblab. Retain the existing image/data volumes when recreating the application
container, then reload browser tabs. Update the optional MCP adapter alongside
the server. The hosted restricted demo is maintained separately.

## Validation

198 backend tests passed, plus LL2S browser checks for the released and legacy
selectors. A disposable lab using the published LL2S image passed RSTP, VLAN
isolation, LLDP, SNMP, shared-console locking, cable-failure recovery and saved ZIP
restore. Mixed-vendor operational console checks exercised the MCP transport;
this is not a claim of complete protocol or real-guest backup coverage for every
vendor. See the development and device guides for limits and reproducible checks.
