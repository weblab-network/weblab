# Weblab v0.8.3

The fresh-install helper now accepts **`--dns IPV4`** to override DNS for the
Weblab core container. Omitting the option preserves Docker's normal DNS settings.

For a non-resolving DNS configuration, choose an address with no responding DNS
service, for example:

```sh
sudo sh weblab-install.sh --dns 127.0.0.199
```

The flag can be combined with `--with-auth`, `--with-agent` and `--start-example`.
With host networking, loopback refers to the Docker host. Normal DNS lookups fail
or time out only if no resolver answers at the selected address. This is **not
Internet isolation**: direct IP access, hosts-file mappings and applications
using their own resolvers can still work. Agent cloud providers requiring DNS
through the core gateway may become unavailable. Host DNS, image pulls, installer
downloads and separate lab-device containers are unaffected.

The installer validates IPv4 syntax before host operations and includes the
selected override in its plan. Regression tests cover invalid inputs, dry runs,
unchanged defaults and applying the setting only to the core container.
See the [installation guide](../installation.md#quick-installer-prebuilt-images)
for the installer download, checksum and manual Docker equivalent.

The existing v0.8.2 tag and installer assets remain unchanged. Core, Agent and
EXOS images use matching **0.8.3** tags; LL2S **0.2.0** and Weblab FRR
**10.7.1-wl1** are unchanged. No application configuration migration is required.
For an existing installation, preserve its volumes and follow the documented
container-recreation procedure; the installer remains for fresh installations.
