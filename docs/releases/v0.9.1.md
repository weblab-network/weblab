# Weblab v0.9.1

More room for large topologies, compact traffic-monitor controls, rectangle
selection and more patient device startup on slower hosts.

## Workspace improvements

- **Layout → Map workspace** fills the visible workspace with the topology below
  one compact toolbar. Agent and Instructions stay on that toolbar; consoles
  and documents float above the map. Devices and Inspector open as overlays.
  The Lab menu keeps lab actions, the topology name and account controls available.
  Layout changes preserve console connections, locks and Agent drafts.
- **Multi-select** supports dragging a rectangle from empty canvas space to
  select every node it touches. Shift/Ctrl/⌘ adds to the existing selection;
  Escape during the drag restores the previous selection. Normal unmodified
  Select mode still pans. Selection works with zoom, scrolling and floating maps.
- **Traffic monitor** capture buttons, filters and Follow move into its title
  bar. The controls scroll horizontally in narrow windows; move, information,
  maximize and close remain accessible. Hover, focus or tap **ⓘ** for capture
  limits and relay semantics. A slim line retains endpoints and capture status.
- Updated documentation screenshot shows Map workspace and actual DTP decoding
  with the compact monitor controls.

See [workspace layouts](https://github.com/weblab-network/weblab/blob/v0.9.1/docs/topology.md)
and [traffic monitoring](https://github.com/weblab-network/weblab/blob/v0.9.1/docs/link-actions.md#monitor-traffic).

## Startup and installer fixes

FRR and LL2S daemon-readiness limits increase from 30 to **120 seconds per node**.
Ready nodes proceed immediately; this adds no fixed delay. Readiness still
checks each device's existing completion signal and fails if it never arrives.

The fresh-install helper now displays the server's error message when an example
startup request fails, instead of only an HTTP 400 traceback. It allows up to
30 minutes for the complete example-start request to accommodate sequential
startup. Failed requests are not automatically retried; inspect the workspace
before recovery. The previously reported slow-VM startup failure lacked its
server error body, so its exact cause remains unconfirmed.

## Installation and upgrade

Use matching **0.9.1** core, Agent and EXOS image tags. The release provides
`weblab-install.sh` and `SHA256SUMS` for fresh installations; the installer is
not an upgrade tool. Back up the lab and preserve its volumes when recreating
existing containers. No configuration migration is required.

See the [installation guide](https://github.com/weblab-network/weblab/blob/v0.9.1/docs/installation.md).
LL2S remains **0.2.0** and Weblab FRR **10.7.1-wl1**; the readiness change is in
Weblab's lifecycle manager, so those device images do not need rebuilding.
