  1. Install with Docker. Clone the repository, start Weblab.Network and open the workspace in your browser. Follow the installation guide for the full requirements and commands.
  2. Upload device images. Add an image through the browser and see it become available for a lab.
  3. Build a topology. Add devices, choose their interfaces, connect nodes and remove a link.
  4. Arrange the workspace. Float device consoles and arrange them beside the topology.
  5. Inspect the network. View Junos, FRR, EXOS and Linux consoles together, including routing, switching and connectivity output.
  6. Inject a link fault. Change a running link's behavior and observe traffic from the PC consoles.
  7. Export a lab. Choose topology JSON or a saved-state ZIP. Vendor base images are supplied separately.

LOOKING AHEAD

What’s next for Weblab.Network

Two directions we plan to explore. These capabilities are not available in the current release, and no delivery dates are set.

PLANNED / AI INTEGRATION

Connect your agent to the lab.

An MCP (Model Context Protocol) interface would let compatible AI agents, including locally hosted models with tool support, create topologies and inspect lab state through controlled tools. Guided exercises and feedback are a longer-term goal.

PLANNED / EDUCATION KIT

A shared workspace for teaching.

Instructor-led labs with user accounts and roles: teachers control the lab and decide what students can observe or change. Limited student permissions and shared demonstrations would support practice without giving every participant full control.
