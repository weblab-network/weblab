01 / THE WORKSPACE

Keep the network in view.

The map explains the connections. The consoles show what the devices are doing. Arrange both around the task at hand.

A layout for the job
Keep the topology full height beside consoles, instructions and Agent. Switch layouts without closing your consoles or drafts.
Shared console, coordinated input
Multiple stations see the same output. Input locks keep operators from typing over each other.
The exercise at your elbow
Open Markdown or text beside the CLI. An admin can publish instructions to every station.
Connect the lab
An optional IPv4 gateway provides outbound NAT and DNS. Build the gateway helper on your Docker host.
Show what sits outside it
Use a Network cloud to draw an unmanaged network. Its dashed connections carry no traffic.
Group a site or routing domain
Add a rectangle with a title and notes. Move enclosed devices together, or keep it as a standalone annotation.

03 / SHARED ACCESS

One lab. Defined responsibilities.

Enable optional authentication for a trusted group. Publish the exercise once, coordinate console ownership, and let each role do its work.

Available in v0.7.0 · three fixed accounts
Account / roleAccess to the shared lab
adminAdministratorPrepare topologies, publish instructions, manage the lab, review activity and use the optional Agent.
userWriterType in consoles, start or stop nodes and operate link faults. Topology structure and instructions stay under admin control.
guestReaderObserve the topology and shared console output. No console input or lab operations.

OPTIONAL / ADMIN AGENT

Prepare. Publish. Verify.

With authentication enabled, Agent access belongs to admin. Lab changes and console input still follow the Agent’s permissions and approval settings.

Read the permissions guide ↗

Authentication is off by default. These are shared accounts in a shared lab, with common console output. They do not provide isolated user environments.

In development: individual users and teaching controls

AAA is an initial implementation. Named users, a live admin panel, per-user node and instruction assignments, and delegated writer Agent access are planned. They remain planned; no delivery date is set.

05 / INSTALLATION

Put a lab on your host.

Start with containers for routing and switching, or bring supported vendor images. Weblab runs the devices on your machine and the workspace in your browser.

HOST REQUIREMENTS

Platform
x86-64 Linux host or VM
Runtime
Rootful Docker + Compose
Virtual devices
KVM for QEMU profiles; vJunos-switch requires bare-metal Intel
Optional
Agent companion · authentication
Open installation guide ↗
  1. 01

    Install the workspace

    Follow the guide for host permissions, persistent storage and remote access. The Agent is a separate Compose option.

  2. 02

    Choose your devices

    Use Weblab FRR routers with LLDP, read-only SNMP, VLAN routing and IPv4 VRRP alongside LL2S switches and Alpine PCs, without KVM. Supported vendor images and licenses are user-supplied.

    Device profiles ↗
  3. 03

    Run an exercise

    Build a topology or import an example. Check device state from the consoles, and save configurations before stopping.
